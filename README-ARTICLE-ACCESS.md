# 文章暗号与图片排版

## 更新与部署

文章暗号使用 PostgreSQL 表 `BlogAccess` 和 `BlogUnlockBudget`，不修改已有文章字段。
本次为 `BlogAccess` 增加 `adminBypass` 布尔字段，默认 `false`。
**升级后，已受保护文章的管理员免验证也默认关闭，须在后台逐篇开启。**
请先备份数据库，再拉取代码并运行（已创建过暗号表也要更新结构）：

```sh
docker compose --profile tools build app db-init
docker compose --profile tools run --rm db-init
docker compose up -d --force-recreate app
```

不要删除数据卷。表或新字段尚未创建时服务端将拒绝读取正文，
不会把受保护内容当作公开内容。不要只重启旧镜像或只执行普通构建。

## 后台设置暗号和管理员免验证

位置：**后台 → 博客 → 编辑文章 → 文章暗号**。

- 「需要暗号才能阅读」控制该文章是否保护正文。
- 「管理员免暗号验证」是**每篇文章独立**的选择性开关。
  - 关闭：包括管理员在内，前台正文、译文和评论均需有效解锁凭据。
  - 开启：已登录管理员可直接在前台查看；其他读者仍需暗号。
  - 无论开关如何，管理员的后台编辑权限不受影响，避免把自己锁出管理页。
- 两个开关都必须点击「保存暗号设置」才生效。页面同时显示已保存状态和未保存提示。
- 只改管理员开关不需要重填暗号，也不会改写正文、清空暗号或触发翻译。

新文章先保存为草稿、设置暗号后再发布，避免正文短暂公开。
此设置独立于正文保存。首次开启须填写暗号；之后留空保持原暗号，
输入新值替换，关闭保护并保存则解除保护。旧客户端省略 `adminBypass` 时保留已有设置；新建默认为关闭。

### 为什么没输入暗号也能看

有三种需要区分的状态：

1. 文章实际上还没有开启并保存暗号保护。
2. 文章允许管理员免验证，而且当前浏览器已经登录管理员。
3. 该浏览器此前已正确输入暗号，12 小时解锁记录仍有效。

仅关闭管理员免验证不会使合法的读者解锁记录失效。
请用无痕窗口或清除该站点的文章解锁 Cookie 检查未解锁效果。
修改暗号会立即使旧解锁凭据和旧暗号分享链接失效。

## 带暗号分享链接

在已开启保护的文章编辑页，展开「带暗号的分享链接」。
输入**当前已经保存的暗号**，点击「生成带暗号链接」，校验成功后点击「复制带暗号链接」。
仅在新暗号刚刚保存的当前编辑会话中可复用本地输入；重新打开后台不会从服务器读回暗号。

生成的链接使用 URL 片段，例如（以下暗号仅为示例）：

```text
https://www.example.com/zh/blog/sample#code=example-code
```

- 后台也会校验暗号；管理员免验证不能生成一个暗号错误的链接。
- 生成分享链接不会解锁当前浏览器，不会修改数据库中的暗号。
- 链接中的中文、空格、`+`、`&`、`#` 等通过 `encodeURIComponent` 编码。
- 读者打开后先显示公开标题和解锁界面，浏览器读取链接中的暗号，
  **先从当前地址及历史条目移除暗号，再通过 POST 发送给服务端验证**。
- 校验通过才签发原有 HttpOnly 解锁凭据并刷新正文；错误暗号、重复冲突参数和请求失败不会直接放行。
- 已解锁或允许免验证的管理员不需要重复验证，但地址栏也会清理暗号。
- 六种语言共用同一文章暗号。普通章节锚点不会触发解锁，也不会被删掉。
- 手动输入暗号不会自动把它添加到当前地址；只有显式生成/分享带暗号链接时才携带。
- 分享链接**没有单独的到期时间**，暗号变更后失效；12 小时仅指验证后的浏览器解锁记录。

为兼容手动拼接的链接，也接受 `?code=...`，但不生成这种写法。
查询参数的第一次 GET 请求可能已经记录在服务器、代理或 CDN 日志中，后续清除地址无法撤回。
优先使用 `#code=...`：片段不会随页面 GET 请求发送到服务器。
这不是加密链接；它仍可能被收件人、浏览器扩展、历史同步或页面脚本看到，
**拿到完整链接就相当于拿到暗号，请勿公开发布。**
标题元数据使用 `no-referrer`；这也不能撤回此前发生的记录。

## 验证与保护边界

- 标题、列表、日期、标签及标题 SEO 仍可公开。正文需要输入暗号。
- 同一文章的所有语言版本共用暗号，不能通过切换语言绕过。
- 评论接口也检查解锁状态，防止从讨论内容绕过正文保护。
- 暗号 4–128 个字符，区分大小写与空格。不写进 Markdown，不进入翻译提示词。
- 暗号只保存带随机盐的 scrypt 哈希，不回显明文。
- 正确输入后设置 HttpOnly、SameSite=Lax Cookie；HTTPS 站点使用 Secure。
- 解锁凭据有效期 12 小时，绑定文章 ID 和当前暗号版本。
- 每篇文章共用一个数据库尝试预算：10 分钟最多 30 次有效格式验证，跨进程生效。
  限流属于基础防暴力尝试，不是完整的 DDoS 防护。高访问量可在反向代理加访客级限流。
- 读取页面为动态渲染，正文 JSON API 和相关接口返回 private/no-store。
  CDN/Cloudflare 不应对文章页面或 `/api/*` 强制「缓存所有内容」。

这不是端到端加密或 DRM：标题仍然公开，知道暗号的读者可以复制内容。
已经公开过的正文无法从第三方缓存、截图、浏览器历史或搜索引擎中撤回。
已有 `/media/...` 和外部图片地址仍是公开资源；此功能保护文章正文，
不把已公开的图片自动转成私有附件。敏感附件不要上传到现有公开图片桶。
开启模型翻译时正文仍会发送给管理员配置的模型提供商；暗号不会发送给模型。

## 图片不挤文字

原图片语法不变：

```md
![证件照|120px|float=right](/media/实际图片地址.webp)

## 你的姓名

个人介绍。

### 教育背景

学校和专业。
```

包含环绕图片的正文中，二至六级标题统一左对齐，避免照片旁的居中轴与下方不同。
文章独立的大标题保持原样。照片最多占正文宽度的 28%，与文字之间保持 1.5rem 间距。
实际正文/预览栏宽度不超过 34rem 时，照片改为独立一行，不再压缩旁边文字。
不含环绕图片的文章保留原有标题居中样式。
